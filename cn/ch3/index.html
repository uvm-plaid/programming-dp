差分隐私

学习目标

阅读本章后，您将能够：

  • 定义差分隐私

  • 解释ϵ\epsilonϵ这一重要的隐私参数

  • 应用拉普拉斯机制实现满足差分隐私的计数问询

与kkk-匿名性类似，差分隐私（Differential Privacy） Dwork (2006)Dwork et al. (2006)也是一个用数学语言描述的隐私定义（即可以用数学方法证明发布数据满足此性质）。然而，与kkk-匿名性不同，差分隐私不是数据所具有的属性，而是算法所具有的属性。也就是说，我们可以证明一个算法满足差分隐私。如果想证明一个数据集满足差分隐私，我们需要证明的是产生此数据集的算法满足差分隐私。

首先需要了解的是：如果两个数据集只有一个个体的数据不同，则认为这两个数据集是临近（Neighboring）数据集。

Definition 1 (隐私机制)

一般将满足差分隐私的函数称为一个机制（Mechanism）。如果对于所有临近数据集xxx和x′x'x′，以及所有可能的输出集合SSS（其中SSS指的是"机制输出的集合SSS"），机制FFF均满足

Pr[F(x)∈S]Pr[F(x′)∈S]≤eϵ\frac{\mathsf{Pr}[F(x) \in S]}{\mathsf{Pr}[F(x') \in S]} \leq e^\epsilonPr[F(x′)∈S]Pr[F(x)∈S]​≤eϵ
(1)

则称机制FFF满足ϵ\epsilonϵ-差分隐私。

一般将差分隐私定义中的参数ϵ\epsilonϵ称为隐私参数（Privacy Parameter）或隐私预算（Privacy Budget）。ϵ\epsilonϵ提供了一个旋钮，用来调整差分隐私定义所能提供的"隐私量"。ϵ\epsilonϵ较小时，意味着FFF需要为相似的输入提供非常相似的输出，因此提供更高等级的隐私性。较大的ϵ\epsilonϵ允许FFF给出不那么相似的输出，因此提供更少的隐私性。

请注意，FFF一般是一个随机函数。也就是说，即使给定相同的输入，FFF一般也包含多个可能的输出。因此，FFF输出的概率分布一般不是一个点分布。

在ϵ\epsilonϵ-差分隐私的定义中，概率是基于算法自身的随机性计算的，即基于隐私机制在生成输出时所使用的内部随机性计算的。

这个定义所蕴含的一个重要含义是，无论输入是否包含任意特定个体的数据，FFF的输出总是几乎相同的。换句话说，FFF所引入的随机性应该足够大，使得观察FFF的输出无法判断输入是xxx还是x′x'x′。假设我的数据在xxx中，但不在x′x'x′中。如果攻击者无法确定FFF的输入是xxx还是x′x'x′，则攻击者甚至无法判断输入是否包含我的数据，更无法判断出我的数据是什么了。

我们在实际中应该如何设置ϵ\epsilonϵ，差分隐私才能提供足够的隐私性呢？没人知道这个问题的答案。一般的共识是：将ϵ\epsilonϵ设置为约等于1或者更小的值；大于10的ϵ\epsilonϵ取值意味着大概率无法提供足够的隐私性。但这个经验法则最终可能会被证明是非常保守的。我们后续将会进一步展开讨论这个问题。

Note

为什么SSS是一个集合，而对于单一输出sss，我们记作F(x)∈SF(x) \in SF(x)∈S，而不是F(x)=sF(x) = sF(x)=s？当FFF返回来自连续域（如实数）的元素时，对于所有 xxx，有概率Pr[F(x)=S]=0\mathsf{Pr}[F(x) = S] = 0Pr[F(x)=S]=0（这是连续概率分布的一个性质——详见此处）。为了在连续分布的上下文中使定义有意义，它需要考虑输出的集合SSS，并使用集合包含（∈\in∈）而不是等式。

如果FFF返回离散集合的元素（例如 32 位浮点数），那么定义可以考虑SSS为单一值，并使用等式而不是集合包含：

Pr[F(x)=S]Pr[F(x′)=S]≤eϵ\frac{\mathsf{Pr}[F(x) = S]}{\mathsf{Pr}[F(x') = S]} \leq e^\epsilonPr[F(x′)=S]Pr[F(x)=S]​≤eϵ
(2)

如果你没有学习过概率论，这个定义可能更直观。

拉普拉斯机制¶

差分隐私一般用于回复特定的问询。我们来考虑一个针对人口普查数据的问询。我们首先不使用差分隐私。

import pandas as pd
import numpy as np
from mplfonts import use_font
use_font('SimHei')
import matplotlib.pyplot as plt
plt.style.use('fivethirtyeight')
adult = pd.read_csv("adult_with_pii.csv")

“数据集中有多少个体的年龄大于等于40岁？”

adult[adult['Age'] >= 40].shape[0]
17450

使这个问询满足差分隐私的最简单方法是：在回复结果上增加随机噪声。这里的关键挑战是：既需要增加足够大的噪声，使问询满足差分隐私，但噪声又不能加得太多，否则问询结果就无意义了。为了简化这一过程，差分隐私领域的学者提出了一些基础机制。这些基础机制具体描述了应该增加何种类型的噪声，以及噪声量应该有多大。最典型的基础机制是拉普拉斯机制（Laplace Mechanism） Dwork et al. (2006)。

Definition 2 (拉普拉斯机制)

根据拉普拉斯机制，对于可以输出一个数值型结果的函数f(x)f(x)f(x)，按下述方法定义的F(x)F(x)F(x)满足ϵ\epsilonϵ-差分隐私：

F(x)=f(x)+Lap(sϵ)F(x) = f(x) + \textsf{Lap}\left(\frac{s}{\epsilon}\right)F(x)=f(x)+Lap(ϵs​)
(3)

其中sss是fff的敏感度（Sensitivity），Lap(S)\textsf{Lap}(S)Lap(S)表示以均值为0、放缩系数为SSS的拉普拉斯分布采样。

拉普拉斯分布的概率密度函数（Probability Density Function，PDF）为

f(x)=12Sexp⁡(−∣x∣S)f(x) = \frac{1}{2S} \exp\left(-\frac{|x|}{S}\right)f(x)=2S1​exp(−S∣x∣​)
(4)

函数fff的敏感度是指，当输入以最小的程度发生变化时，fff的输出变化量。直观地说，对于只有一个数值型输入的简单函数，我们考虑的是输入增加或减少（变化）1的情况。

然而，更一般地，我们用相邻数据集输入来定义敏感度。

如果两个数据集只有一个个体的数据不同，则称这两个数据集是相邻（Adjacent）的。这既可以指添加或删除一行数据（增删模型），也可以指修改一行数据（替换模型）。相邻性定义了数据集之间可能存在的最小差异，是推导隐私保证的基础。

函数fff的全局敏感度（Global Sensitivity）一般定义为：对于任意一对相邻的输入数据集，fff的输出可能发生的最大变化量。

计算函数fff的敏感度是一个非常复杂的问题，也是设计差分隐私算法时所需面临的核心问题，我们稍后会更进一步展开讨论。我们现在只需要指出，计数问询（Counting Query）的敏感度总为1：当问询数据集中满足特定属性的数据量时，如果我们只修改数据集中的一个数据项，则问询的输出变化量最多为1。

因此，我们可以根据我们所选择的ϵ\epsilonϵ，在计数问询中使用敏感度等于1的拉普拉斯机制，从而使我们的样例问询满足差分隐私性。现在，我们取ϵ=0.1\epsilon = 0.1ϵ=0.1。我们可以用Numpy的random.laplace函数实现拉普拉斯分布采样。

sensitivity = 1
epsilon = 0.1

adult[adult['Age'] >= 40].shape[0] + np.random.laplace(loc=0, scale=sensitivity/epsilon)
17420.586602042986

可以试着多次运行此代码，查看噪声对问询结果造成的影响。虽然每次代码的输出结果都会发生变化，但在大多数情况下，输出的结果都与真实结果（14,235）很接近，输出结果的可用性相对较高。

需要多大的噪声？¶

我们如何知道拉普拉斯机制是否已经增加了足够的噪声，可以阻止攻击者对数据集中的个体实施重标识攻击？我们可以先尝试自己来实施攻击！我们构造一个恶意的计数问询，专门用于确定凯莉·特鲁斯洛夫的收入是否大于$50k。

karries_row = adult[adult['Name'] == 'Karrie Trusslove']
karries_row[karries_row['Target'] == '<=50K'].shape[0]
1

此回复结果给出了凯莉所在数据行的收入值，显然侵犯了凯莉的隐私。由于我们知道如何应用拉普拉斯机制使计数问询满足差分隐私，我们可以这样回复问询：

sensitivity = 1
epsilon = 0.1

karries_row = adult[adult['Name'] == 'Karrie Trusslove']
karries_row[karries_row['Target'] == '<=50K'].shape[0] + \
  np.random.laplace(loc=0, scale=sensitivity/epsilon)
-2.677769385984818

真实结果是0还是1呢？因为增加的噪声比较大，我们已经无法可靠地判断真实结果是什么了。这就是差分隐私要实现的目的：哪怕可以判定出此问询是恶意的，我们也不会拒绝回复问询。相反，我们会增加足够大的噪声，使恶意问询的回复结果对攻击者来说变得毫无用处。

随机性与可复现性

本书中的一些示例使用了随机算法，尤其是在演示向数据或模型更新中添加噪声的差分隐私机制时。由于我们没有固定随机种子，这些示例每次运行的具体输出结果都会有所不同。这种变化是符合预期的，也是差分隐私的自然结果，因为差分隐私依赖随机性来提供隐私保护。

如果你得到的结果与书中给出的结果略有不同，这不是缺陷，而是特性。即使具体数值有所不同，算法的基本行为也应该保持一致。如果需要精确复现结果（例如用于测试或调试），可以使用Python中的np.random.seed()或random.seed()等工具设置固定的随机种子。不过，出于教学目的，我们选择不固定随机种子，使示例能够反映隐私算法在实际中的真实行为。

隐私单元¶

差分隐私的典型定义将临近数据集定义为任意两个只有“一个个体的数据”不同的数据集。通常很难或不可能弄清有多少数据“属于”哪个个体。

隐私单元（Unit of Privacy）指的是差分隐私保证中使用的“临近”的形式化定义。最常见的隐私单元是“一个个体”——这意味着隐私保证永远保护整个个体。这通常也被称为“用户级隐私”（User-Level Privacy）。

但也可以有其他定义；例如，苹果公司的差分隐私实现使用的隐私单元是“个体-日”，即隐私保证适用于一个个体在一天内提交的数据。

隐私单元可能导致出人意料的隐私失效。例如，在苹果的系统中，差分隐私保证并不能保护数据在多天内的趋势，即使是对个体而言也是如此。如果一个个体连续365天提交完全相同的数据，那么差分隐私基本上不会对这些数据提供保护。

用“一个个体”作为隐私单元是一个很好的默认值，通常可以避免意外情况。其他隐私单元通常用于更容易获得准确的结果，或者因为很难将特定数据值与个体联系起来。

我们通常会做一个简化假设，使得形式化定义临近数据集变得容易：

  • 每个个体的数据恰好包含在数据的一行中

如果这个假设成立，那么可以根据数据的格式（见下文）形式化地定义临近数据集，并保持所需的“一个个体”隐私单元。当假设不成立时，最好的解决方案是转换数据和问询，以实现“一个个体”隐私单元。应尽可能避免使用不同的隐私单元。

替换相邻性与增删相邻性¶

在“一个个体 = 一行数据”的简化假设下，临近数据集之间只有一行数据不同。“不同”是什么意思？这也有两种定义方式！以下是两个形式化定义：

Definition 3 (替换相邻性)

在替换相邻性（Substitution Adjacency）下，如果数据集 x′x'x′ 可以通过修改 xxx 中的一行得到，则认为 xxx 和 x′x'x′ 是临近数据集。在替换相邻性下，xxx 和 x′x'x′ 的大小相同。

Definition 4 (增删相邻性)

在增删相邻性（Add-Remove Adjacency）下，如果数据集 x′x'x′ 可以通过在 xxx 中添加或删除一行得到，则认为 xxx 和 x′x'x′ 是临近数据集。在增删相邻性下，xxx 和 x′x'x′ 的大小不同（相差一行）。

总结

  • 差分隐私是算法的属性，而不是数据的属性。

  • 满足差分隐私的函数通常称为机制。

  • 实现该函数差分隐私的最简单方法是向其答案添加随机噪声。

  • 隐私单元指的是差分隐私保证中使用的“临近”的形式化定义。最常见的隐私单元是“一个个体”——这意味着隐私保证保护整个个体，永久有效。
