k-匿名性

kkk-匿名性（kkk-Anonymity）Sweeney (2002)是一个用数学语言描述的隐私定义。kkk-匿名性的定义用数学描述了我们的直观想法：一部分辅助信息不应该"过多地"缩小个体所属记录的可能范围。换句话说，kkk-匿名性的目的是为了保证每个个体都能"融入人群"。

学习目标

阅读本章后，你将会理解：

  • kkk-匿名性的定义

  • 如何验证数据集是否满足kkk-匿名性

  • 如何泛化数据集，使数据集满足kkk-匿名性

  • kkk-匿名性的局限性。

把数据集按照数据集各个列中的特定子集分组，即按照准标识（Quasi-Identifier）分组，使每个分组中的个体都拥有相同的准标识。如果数据集中的每个个体所属分组的大小都至少为kkk，则我们称此数据集满足kkk-匿名性。此时，每个个体都"融入"其所在的分组中了。这样一来，虽然攻击者仍然可以将攻击范围缩小至特定的分组中，但攻击者无法进一步确定分组中的哪个个体才是攻击目标。

Definition 1 (k-匿名性)

用数学语言描述此概念，对于特定的kkk，如果：

  • 对于任意记录r1∈Dr_1 \in Dr1​∈D，存在至少k−1k - 1k−1条其他的记录r2…rk∈Dr_2 \dots r_k \in Dr2​…rk​∈D，使得Πqi(D)r1=Πqi(D)r2,…,Πqi(D)r1=Πqi(D)rk\Pi_{qi(D)} r_1 = \Pi_{qi(D)} r_2, \dots, \Pi_{qi(D)} r_1 = \Pi_{qi(D)} r_kΠqi(D)​r1​=Πqi(D)​r2​,…,Πqi(D)​r1​=Πqi(D)​rk​

其中qi(D)qi(D)qi(D)是DDD的准标识，Πqi(D)r\Pi_{qi(D)} rΠqi(D)​r表示包含准标识的列rrr（即准标识的投影），则称数据集DDD满足kkk-匿名性。

并且，准标识qi\mathit{qi}qi被假定为是事先固定的，即在执行任何匿名化处理之前就已知并指定好的。这反映了攻击者模型：我们假设攻击者可以利用qi\mathit{qi}qi中的属性实施关联攻击。

验证kkk-匿名性¶

我们先从一个小数据集开始。我们可以直接查看小数据集所包含的数据，从而直观判断出此数据集是否满足kkk-匿名性。这个数据集包含年龄列和两个考试分数列。很明显，对于任意k>1k > 1k>1，此数据集都不满足kkk-匿名性。任何数据集都天然满足k=1k = 1k=1的kkk-匿名性，因为任意记录自身都可以构成一个大小为1的分组。

我们要实现一个验证数据帧是否满足kkk-匿名性的函数。为此，我们循环检查每一行数据，查看数据帧中有多少行数据与当前数据的准标识相匹配。如果任何分组包含记录的数量小于kkk，就意味着数据帧不满足kkk-匿名性，我们返回False。需要注意的是，在这个简单的例子中，我们把所有列都定义为了准标识。只需要将df.columns替换为子列，就可以只把某些列作为准标识了。

def isKAnonymized(df, k):
    for index, row in df.iterrows():
        query = ' & '.join([f'{col} == {row[col]}' for col in df.columns])
        rows = df.query(query)
        if rows.shape[0] < k:
            return False
    return True

验证结果满足预期，我们的示例数据帧在k=2k = 2k=2时不满足kkk-匿名性，但此数据帧满足k=1k = 1k=1的kkk-匿名性。

isKAnonymized(df, 1)
True
isKAnonymized(df, 2)
False

泛化数据以满足kkk-匿名性¶

一般通过泛化（Generalization）数据的方式对数据集进行修改，使其满足特定取值kkk下的kkk-匿名性。泛化指的是将数据修改为不那么特殊的数据，使其更可能与数据集中其他个体的数据相匹配。举例来说，精确到个位的年龄可以通过四舍五入的方式泛化为精确到十位，可以将邮政编码最右侧的数字替换为0来泛化邮政编码。很容易对数值型数据进行泛化处理。我们这里使用数据帧的apply函数完成数值型数据的泛化处理。在apply函数中传入名为depth的查找表，查找表中存储每一列要用0替换多少位数字。通过这种方式，我们可以灵活地对不同的列进行不同级别的泛化处理。

def generalize(df, depths):
    return df.apply(lambda x: x.apply(lambda y: int(int(y/(10**depths[x.name]))*(10**depths[x.name]))))

现在，我们可以对示例数据帧进行泛化处理了。首先，我们尝试对每一列数据进行"一层"泛化，即四舍五入到十位。

depths = {

    'preTestScore': 1,
    'postTestScore': 1
}
df2 = generalize(df, depths)

引入更多的数据可以减小泛化的影响吗？¶

我们的示例数据集太小了。这个数据集中只包含5个个体，很难构建包含2个或更多具有相同属性的个体分组，因此很难让这样的数据集满足kkk-匿名性。解决这个问题的方法是引入更多的数据：在拥有更多个体的数据集中，通常需要更少的泛化处理即可使数据集满足所需kkk取值下的kkk-匿名性。

让我们来试试去标识那一章中的人口普查数据。这个数据集包含超过32,000行数据，因此应该更容易满足kkk-匿名性。

adult_data = pd.read_csv("adult_with_pii.csv")
adult_data.head()

我们把每个个体的年龄和受教育年数作为准标识。我们只保留这两列数据，尝试实现k=2k = 2k=2下的kkk-匿名性。此数据集已经先天满足k=1k = 1k=1下的kkk-匿名性了。

请注意，我们验证数据集中的前100行数据是否满足kkk-匿名性。如果尝试在更大子集的数据下执行isKAnonymized函数，会发现验证过程需要花费很长一段时间（例如，在我们的笔记本电脑上验证5000行数据是否满足k=1k = 1k=1的kkk-匿名性，大约需要花费20秒的时间）。当k=2k = 2k=2时，我们的算法很快就找到了不满足要求的行，快速完成了验证。

泛化结果仍然无法满足k=2k = 2k=2的kkk-匿名性！事实上，即使对所有32,000行数据都进行类似的泛化处理，泛化结果依然无法满足k=2k = 2k=2的kkk-匿名性。因此，引入更多数据并不一定像我们期待的那样降低满足kkk-匿名性的难度。

出现这一问题的根本原因是，数据集中包含异常值（Outlier），即包含一些与其他个体差异非常大的个体。即使经过了泛化处理，也很难使这些异常个体融入到任何分组中。即使只考虑年龄，我们也能看出引入更多的数据不太可能有所帮助，因为数据集中年龄极低和极高的个体都很少。

当数据集中包含异常值时，实现满足kkk-匿名性的最优泛化方法是一个非常有挑战性的任务。进一步泛化每一行数据会过分泛化年龄在20-40范围内的数据，损害结果数据的可用性。然而，为了满足kkk-匿名性，显然还需要对年龄进一步泛化，更大地放宽年龄取值的上下界。这是实际使用kkk-匿名性时人们经常需要面对的一种挑战，很难通过自动化的方式解决。实际上，实现满足kkk-匿名性的最优泛化方法已经被证明是一个NP-困难问题。

Note

Meyerson和Williams在2004年发表的论文《On the Complexity of Optimal kkk-Anonymity》Meyerson & Williams (2004)中证明：在最小化信息损失的前提下，寻找能使数据集满足kkk-匿名性的最优泛化方法是一个NP-困难问题。这一结果凸显了在实际中自动实现kkk-匿名性的难度：即使数据集规模或kkk的取值并不大，找到最佳泛化方法在计算上也可能是不可行的。

Important

异常值使得实现kkk-匿名性变得非常具有挑战性，即使对于较大的数据集也是如此。实现满足kkk-匿名性的最优泛化方法是一个NP-困难问题。

移除异常值¶

异常值问题的一个简单解决方案是将数据集中每个个体的年龄限制在一个特定的范围内，从而完全消除数据集中的异常值。这种方法也会损害数据的可用性，因为这种方法需要用假的年龄值替代真实的年龄值，但这可能比进一步泛化每一行数据要好。我们可以使用Numpy的clip（裁剪）函数来实施这一解决方案。我们将年龄裁剪到10至60岁之间，并要求受教育水平至少为小学五至六年级（在数据集中用索引3表示）。

# 裁剪异常值
depths = {
    'age': 1,
    'edu': 1
}
dfp = df.clip(upper=np.array([60, 100000000]), axis='columns')
dfp = dfp.clip(lower=np.array([10, 3]), axis='columns')
df2 = generalize(dfp.head(500), depths)
isKAnonymized(df2, 7)
True

现在，我们将数据集泛化到满足k=7k = 7k=7的kkk-匿名性了！换句话说，我们终于把数据集泛化到了合适的程度。在这一过程中，异常值为满足kkk-匿名性带来了相当多的障碍，甚至使我们很难将数据泛化到满足k=2k = 2k=2的kkk-匿名性。

我们后续还将在限定函数敏感度以实现差分隐私的场景下进一步讨论裁剪。

裁剪与分桶

虽然裁剪（Clipping）和分桶（Bucketing）都会降低数据的粒度，但二者的用途不同。裁剪适用于处理不希望出现的极端值，例如截断异常高的年龄，从而限制异常值对统计问询的影响。

另一方面，分桶用于构建有意义的类别（例如年龄段），以便进行分类、比较或泛化。

简而言之，裁剪是限定（敏感度）边界的工具，而分桶有助于组织数据结构，以便进行分析或匿名化处理！

同质性攻击¶

同质性攻击是对kkk-匿名性有效性的重要限制。通常，kkk-匿名性的目标是通过确保数据集中每个个体与至少其他k−1k-1k−1个个体无法区分来保护个体的身份。这些k−1k-1k−1个体（加上该个体本身）被称为数据集内该个体的“组”。

然而，同质性攻击利用组内准标识符的相似性，使得实现真正的个体匿名性变得具有挑战性。在这种攻击中，攻击者利用用于匿名化的属性之间的一致性或缺乏多样性，从而实现个体的去匿名化/重新识别。

当数据的准标识符表现出高度相似性，并且组内的敏感属性值相同，这种攻击向量就会出现，使得攻击者更容易推断出特定个体的敏感信息。在这种情况下，可以通过确定组成员身份推断出个体的敏感信息。

Note

值得注意的是，kkk-匿名性也非常容易受到由个体背景知识的可用性所启用的攻击。这种知识可能通过简单的排除不符合某些标准的组内其他成员来帮助重新识别个体。

解决同质性攻击需要仔细手动选择多样化的准标识符，强调了需要更复杂的匿名化技术来增强数据集中隐私保护的稳健性。

一种免受背景知识影响的技术便是差分隐私。

深入理解同质性攻击

同质性攻击（Homogeneity Attack）利用的是分组内所有（或几乎所有）记录都具有相同敏感属性值的情况。即使移除了显式的标识信息，攻击者也可以借此以很高的置信度推断出敏感信息。

我们把同质性攻击应用到一个示例中，使其更加具体。示例中的医疗数据集包含Zip Code（邮政编码）、Age（年龄）、Gender（性别）等属性，以及一个额外添加的敏感属性Diagnosis（诊断结果）。

假设我们已经使用**kkk-匿名性**对数据进行了匿名化处理，发布的数据集中包含下述经过泛化处理的记录分组：

邮政编码年龄性别诊断结果
0213830–40男流感
0213830–40男流感
0213830–40男流感

此分组满足3-匿名性，因为分组中包含三条无法区分的记录。然而，这三条记录的诊断结果都相同：流感。如果攻击者知道一个名叫亚历克斯（Alex）的人是居住在02138地区的35岁男性，攻击者就可以很有把握地将亚历克斯关联到此分组。尽管攻击者无法确定哪条记录属于亚历克斯，但由于敏感属性缺乏多样性，攻击者仍然可以推断出他的诊断结果。

这就是同质性攻击的本质：匿名集合足够大，但敏感属性不够多样。

为什么这很重要¶

kkk-匿名性保证每个个体都无法与至少k−1k - 1k−1个其他个体区分开来，但kkk-匿名性无法保证这些个体的敏感属性值不全都相同。因此，如果分组内的敏感属性缺乏变化，隐私就无法得到保护。

为了缓解这一问题，人们提出了**ℓ\ellℓ-多样性**（ℓ\ellℓ-Diversity）和**ttt-接近性**（ttt-Closeness）等技术。这些方法的目标是确保在每个匿名分组内，敏感属性的分布依然具有多样性，并且与整体分布相似。

然而，即使是这些改进方法也存在局限性，尤其是在高维数据集中，或者当攻击者掌握大量辅助知识时。这也是采用差分隐私的动机之一：差分隐私既不依赖于对记录进行分组，也不依赖于对攻击者知识的假设。

总结

  • kkk-匿名性是数据集所满足的一种性质，此性质要求每个个体都"融入"到至少包含kkk个人的一个分组中。

  • 检查数据集是否满足kkk-匿名性的计算开销是很大的：朴素算法的计算复杂度是O(n2)O(n^2)O(n2)，更快的算法需要占用相当大的存储空间。

  • 可以通过泛化使数据集满足kkk-匿名性：泛化是指修改数据集中的数据，将特定的取值替换为更一般的取值，使数据更容易形成分组。

  • 实现最优泛化方法是及其困难的，异常值的存在使得泛化变得更具有挑战性。实现满足kkk-匿名性的最优泛化方法是一个NP-困难问题。
