k-Anonymity

kkk-Anonymity Sweeney (2002) is a formal privacy definition. The definition of kkk-Anonymity is designed to formalize our intuition that a piece of auxiliary information should not narrow down the set of possible records for an individual “too much.” Stated another way, kkk-Anonymity is designed to ensure that each individual can “blend into the crowd.”

Learning Objectives

After reading this chapter, you will understand:

  • The definition of kkk-Anonymity

  • How to check for kkk-Anonymity

  • How to generalize data to enforce kkk-Anonymity

  • The limitations of kkk-Anonymity

Informally, we say that a dataset is “kkk-Anonymized” for a particular kkk if each individual in the dataset is a member of a group of size at least kkk, such that each member of the group shares the same quasi-identifiers (a selected subset of all the dataset’s columns) with all other members of the group. Thus, the individuals in each group “blend into” their group - it’s possible to narrow down an individual to membership in a particular group, but not to determine which group member is the target.

Definition 1 (K-Anonymity)

Formally, we say that a dataset DDD satisfies kkk-Anonymity for a value of kkk if:

  • For each row r1∈Dr_1 \in Dr1​∈D, there exist at least k−1k-1k−1 other rows r2…rk∈Dr_2 \dots r_k \in Dr2​…rk​∈D such that Πqi(D)r1=Πqi(D)r2,…,Πqi(D)r1=Πqi(D)rk\Pi_{qi(D)} r_1 = \Pi_{qi(D)} r_2, \dots, \Pi_{qi(D)} r_1 = \Pi_{qi(D)} r_kΠqi(D)​r1​=Πqi(D)​r2​,…,Πqi(D)​r1​=Πqi(D)​rk​

where qi(D)qi(D)qi(D) is the quasi-identifiers of DDD, and Πqi(D)r\Pi_{qi(D)} rΠqi(D)​r represents the columns of rrr containing quasi-identifiers (i.e. the projection of the quasi-identifiers).

and the quasi-identifier qi\mathit{qi}qi is assumed to be fixed a priori—that is, known and specified before any anonymization is performed. This reflects the attacker model: we assume the adversary can use qi\mathit{qi}qi attributes to perform linkage attacks.

Checking for kkk-Anonymity¶

We’ll start with a small dataset, so that we can immediately see by looking at the data whether it satisfies kkk-Anonymity or not. This dataset contains age plus two test scores; it clearly doesn’t satisfy kkk-Anonymity for k>1k > 1k>1. Any dataset trivially satisfies kkk-Anonymity for k=1k = 1k=1, since each row can form its own group of size 1.

To implement a function to check whether a dataframe satisfies kkk-Anonymity, we loop over the rows; for each row, we query the dataframe to see how many rows match its values for the quasi-identifiers. If the number of rows in any group is less than kkk, the dataframe does not satisfy kkk-Anonymity for that value of kkk, and we return False. Note that in this simple definition, we consider all columns to contain quasi-identifiers; to limit our check to a subset of all columns, we would need to replace the df.columns expression with something else.

def isKAnonymized(df, k):
    for index, row in df.iterrows():
        query = ' & '.join([f'{col} == {row[col]}' for col in df.columns])
        rows = df.query(query)
        if rows.shape[0] < k:
            return False
    return True

As expected, our example dataframe does not satisfy kkk-Anonymity for k=2k = 2k=2, but it does satisfy the property for k=1k=1k=1.

isKAnonymized(df, 1)
True
isKAnonymized(df, 2)
False

Generalizing Data to Satisfy kkk-Anonymity¶

The process of modifying a dataset so that it satisfies kkk-Anonymity for a desired kkk is generally accomplished by generalizing the data - modifying values to be less specific, and therefore more likely to match the values of other individuals in the dataset. For example, an age which is accurate to a year may be generalized by rounding to the nearest 10 years, or a ZIP code might have its rightmost digits replaced by zeros. For numeric values, this is easy to implement. We’ll use the apply method of dataframes, and pass in a dictionary named depths which specifies how many digits to replace by zeros for each column. This gives us the flexibility to experiment with different levels of generalization for different columns.

def generalize(df, depths):
    return df.apply(lambda x: x.apply(lambda y: int(int(y/(10**depths[x.name]))*(10**depths[x.name]))))

Now, we can generalize our example dataframe. First, we’ll try generalizing each column by one “level” - i.e. rounding to the nearest 10.

depths = {

}
df2 = generalize(df, depths)

Does More Data Improve Generalization?¶

Our example dataset is too small for kkk-Anonymity to work well. Because there are only 5 individuals in the dataset, building groups of 2 or more individuals who share the same properties is difficult. The solution to this problem is more data: in a dataset with more individuals, less generalization will typically be needed to satisfy kkk-Anonymity for a desired kkk.

Let’s try the same census data we examined for de-identification. This dataset contains more than 32,000 rows, so it should be easier to achieve kkk-Anonymity.

adult_data = pd.read_csv("adult_with_pii.csv")
adult_data.head()

We’ll consider the age and educational achievement of each individual to be the quasi-identifiers. We’ll project just those columns, and try to achieve kkk-Anonymity for k=2k=2k=2. The data is already kkk-Anonymous for k=1k=1k=1.

Notice that we take just the first 100 rows from the dataset for this check - try running isKAnonymized on a larger subset of the data, and you’ll find that it takes a very long time (for example, running the k=1k=1k=1 check on 5000 rows takes about 20 seconds on our laptop). For k=2k=2k=2, our algorithm finds a failing row quickly and finishes fast.

df = adult_data[['Age', 'Education-Num']]

Now, we’ll try to generalize to achieve kkk-Anonymity for k=2k=2k=2. We’ll start with generalizing both age and educational attainment to the nearest 10.

# outliers are a real problem!
depths = {

The generalized result still does not satisfy kkk-Anonymity for k=2k=2k=2! In fact, we can perform this generalization on all ~32,000 rows and still fail to satisfy kkk-Anonymity for k=2k=2k=2 - so adding more data does not necessarily help as much as we expected.

The reason is that the dataset contains outliers - individuals who are very different from the rest of the population. These individuals do not fit easily into any group, even after generalization. Even considering only ages, we can see that adding more data is not likely to help, since very low and very high ages are poorly represented in the dataset.

Achieving the optimal generalization for kkk-Anonymity is very challenging in cases like this. Generalizing each row more would be overkill for the well-represented individuals with ages in the 20-40 range, and would hurt utility. However, more generalization is clearly needed for individuals at the upper and lower ends of the age range. This is the kind of challenge that occurs regularly in practice, and is difficult to solve automatically. In fact, optimal generalization for kkk-Anonymity has been shown to be NP-hard.

Note

In their 2004 paper Meyerson & Williams (2004) , On the Complexity of Optimal kkk-Anonymity, Meyerson and Williams proved that the problem of finding an optimal generalization of a dataset to satisfy kkk-anonymity, while minimizing information loss, is NP-hard. This result underscores the difficulty of automating kkk-anonymity in practice: even for modest dataset sizes or values of kkk, it may be computationally infeasible to find the best generalization.

Important

Outliers make achieving kkk-Anonymity very challenging, even for large datasets. Optimal generalization for kkk-Anonymity is NP-hard.

Removing Outliers¶

One solution to this problem is simply to clip the age of each individual in the dataset to lie within a specific range, eliminating outliers entirely. This can also hurt utility, since it replaces real ages with fake ones, but it can be better than generalizing each row more. We can use Numpy’s clip method to perform this clipping. We clip ages to be 10-60, and require an educational level of at least 5th-6th grade (represented by the index 3 in the dataset).

# clipping away outliers
depths = {
    'age': 1,
    'edu': 1
}
dfp = df.clip(upper=np.array([60, 100000000]), axis='columns')
dfp = dfp.clip(lower=np.array([10, 3]), axis='columns')
df2 = generalize(dfp.head(500), depths)
isKAnonymized(df2, 7)
True

Now, the generalized dataset satisfies kkk-Anonymity for k=7k=7k=7! In other words, our level of generalization was appropriate, but outliers prevented us from achieving kkk-Anonymity before, even for k=2k=2k=2.

We will also discuss clipping later on in the context of bounding function sensitivity in order to achieve differential privacy.

Clipping Vs. Bucketing

While both clipping and bucketing reduce the granularity of data, they serve different purposes. Clipping is useful for dealing with unwanted extremes —for example— truncating unusually high ages to limit outliers’ influence on statistical queries.

Bucketing, on the other hand, is used to create meaningful categories—such as age groups—for classification, comparison, or generalization.

In short, clipping is a tool for bounding (sensitivity), while bucketing helps structure the data for analysis or anonymization!

The Homogeneity Attack¶

The homogeneity attack represents a significant limitation to the effectiveness of kkk-Anonymity. Ordinarily, the goal of kkk-Anonymity is to protect individuals’ identities by ensuring that each individual in a dataset is indistinguishable from at least k−1k-1k−1 others. These k−1k-1k−1 others (in addition to the individual) are called the individual’s “group” within the dataset.

However, the homogeneity attack leverages similarities among quasi-identifiers within a group, making it challenging to achieve true individual anonymity. In this attack, an adversary exploits the uniformity or lack of diversity among the attributes used for anonymization, enabling the de-anonymization/re-identification of individuals.

This attack vector arises when the data’s quasi-identifiers exhibit a high degree of similarity, and groups have identical values for their sensitive attributes, making it easier for an attacker to infer sensitive information about specific individuals. In such cases, sensitive information regarding individuals can be inferred via determination of group membership.

Note

It is worth noting that kkk-Anonymity is also highly susceptible to attacks enabled by the availability of background knowledge regarding individuals. Such knowledge may aid, for example, in re-identification of individuals by simple process of elimination of other members of their group who do not fit certain criteria.

Addressing the homogeneity attack requires careful manual consideration regarding the selection of diverse quasi-identifiers, highlighting the need for more sophisticated anonymization techniques to enhance the robustness of privacy preservation in datasets.

One such technique, which is also immune to the presence of background knowledge, is differential privacy.

The Homogeneity Attack: A Closer Look

The homogeneity attack exploits situations where all—or nearly all—records in a group share the same sensitive attribute. Even if explicit identifiers are removed, this can allow an adversary to confidently infer sensitive information.

Let’s make this concrete by applying it to our running example, which involves a medical dataset with attributes like Zip Code, Age, Gender, and an added sensitive attribute Diagnosis.

Suppose the data has been anonymized using kkk-anonymity, and the following generalized record group appears in the released dataset:

Zip CodeAgeGenderDiagnosis
0213830–40MaleFlu
0213830–40MaleFlu
0213830–40MaleFlu

This group satisfies 3-anonymity, as there are three indistinguishable records. However, all of them share the same diagnosis: Flu. If an attacker knows that someone named Alex is a 35-year-old male living in 02138, they can confidently link Alex to this group. Even though they cannot pinpoint which record is his, the lack of diversity in the sensitive attribute allows them to infer his diagnosis.

This is the essence of the homogeneity attack: the anonymity set is large enough, but it’s not diverse enough in the sensitive attribute.

Why This Matters¶

kkk-anonymity guarantees that an individual is indistinguishable from at least k−1k - 1k−1 others, but it does not guarantee that those others don’t all share the same sensitive value. As a result, privacy is not preserved if the sensitive attribute lacks variability within the group.

To mitigate this, techniques like ℓ\ellℓ-diversity and ttt-closeness were introduced. These methods aim to ensure that, within each anonymity group, the distribution of the sensitive attribute remains varied and resembles the overall distribution.

However, even these refinements have limitations—especially in high-dimensional datasets or under strong auxiliary knowledge. This is one of the motivations for adopting differential privacy, which does not rely on grouping records or assumptions about adversary knowledge.

Summary

  • kkk-Anonymity is a property of data, which ensures that each individual “blends in” with a group of at least kkk individuals.

  • kkk-Anonymity is computationally expensive even to check: the naive algorithm is O(n2)O(n^2)O(n2), and faster algorithms take considerable space.

  • kkk-Anonymity can be achieved by modifying a dataset by generalizing it, so that particular values become more common and groups are easier to form.

  • Optimal generalization is extremely difficult, and outliers can make it even more challenging. Solving this problem automatically is NP-hard.
